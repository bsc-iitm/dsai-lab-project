Milestones

Milestone 1

Deadline: October 22

The requirements of Milestone 1 include defining the problem statement clearly and identifying gaps and opportunities by studying current solutions.

Problem Statement

  • Clearly and concisely describe the problem your project intends to solve.
  • Define the scope and boundaries of the project.
  • Identify the relevant stakeholders.
  • State the objectives of the project. Ensure they are measurable and aligned with the problem statement.

Literature Review & Existing Solutions

  • Research and review current solutions, tools, and academic work related to your problem.
  • Analyze the strengths and weaknesses of current approaches. Compare these with your approach and highlight key differences.
  • Include performance benchmarks, industry standards, baseline models, and evaluation metrics, as applicable.
  • Include references from credible sources in the submission.

Submission

  • The submission should be completed in Markdown format and uploaded to the GitHub repository.
  • A detailed file tracking the work completed by each team member should be included. This file must be updated with every milestone submission.

A milestone review meeting will be held after the submission. During this meeting, the group is expected to present their work in detail using slides.

The respective TAs for each group will reach out to finalize the time slot for the milestone review meetings.

If you have any questions, feel free to reach out in the group chat space.

Milestone 2

Deadline: October 29

The requirements of Milestone 2 include identifying (or creating) the dataset and preparing it for ingestion into the model pipeline.

The objective is to ensure that the data is well-understood, reliable, ethically sourced, and suitably structured for the selected problem.

Dataset & Data Sources

The submission should address the following aspects, as applicable to the project type:

  • Clearly identify and verify data sources.

  • Specify the ownership, format, and usage constraints of the data.

  • Provide a detailed description of the dataset, including:

    • Dataset size
    • Feature distribution
    • Relevant data characteristics

  • Assess dataset quality, accounting for:

    • Missing values
    • Inconsistencies
    • Noise
    • Duplicate entries

  • Evaluate whether the dataset is adequate for the chosen problem.

  • Explore options such as data augmentation or expansion through supplementary datasets where necessary.

Dataset Splits

  • Clearly define the strategy used to create the training, validation, and test datasets.
  • Ensure there is no data leakage by checking for overlap across the different splits.

Synthetic Data

If a synthetic dataset is generated:

  • Provide details of the generation process.
  • Explain and justify the design choices made.

Multiple Datasets & Subtasks

For models involving subtasks that require different datasets:

  • Clearly explain how connections or alignment between the datasets and tasks will be established.

Model-Specific Data Requirements

Identify the key dataset requirements necessary for effective model training.

Vision-Based Tasks

  • Specify labeling and annotation requirements.
  • Verify the quality and consistency of annotations.

RAG-Based Setups

  • Describe document preparation steps.
  • Explore appropriate chunking strategies.
  • Explore suitable vector database options.

Speech-Based Tasks

Address:

  • Audio quality
  • Transcription alignment
  • Sampling consistency

LLM Fine-Tuning Tasks

Address:

  • Dataset formatting, such as instruction-response structures
  • Token length considerations
  • Prompt structuring requirements

Reproducibility

Document all preprocessing and data preparation steps to ensure that the process is reproducible.

Milestone 3

Deadline: November 5

The requirements of Milestone 3 include the design and justification of the model architecture.

The milestone should also verify the complete end-to-end pipeline by running a subset of the data to confirm that all components work together correctly.

Dataset Organization & Preprocessing

The submission should address the following aspects, as applicable to the project type:

  • Explain how the dataset is organized.

  • Showcase the directory structure for:

    • Raw data
    • Processed data
    • Training split
    • Validation split
    • Test split

  • Provide a detailed description of the preprocessing steps applied to the dataset before training.

Examples include:

  • Resizing
  • Normalization
  • Tokenization
  • Other task-specific preprocessing

Model Architecture

  • Provide a clear description of the architecture, highlighting the major components of the network and their interactions.
  • Use a diagram to illustrate the data flow from raw input to final model output.
  • Explain how the processed data matches the expected input format of the model.

This should include, as applicable:

  • Input shapes
  • Tensor formats
  • Token lengths
  • Embedding structures
  • Other architecture-specific input requirements

Architecture Justification

  • Explain why the chosen architecture is suitable for the problem.
  • Discuss the key strengths and limitations of the model.
  • Compare the chosen architecture with other relevant approaches.

End-to-End Pipeline

  • Implement a small-scale pipeline by passing a subset of the dataset through the complete workflow.
  • The purpose is to verify that all components of the pipeline work together correctly.
  • Provide examples of the model outputs.

Loss & Evaluation

  • State the loss functions used.
  • State the evaluation metrics used to measure model performance.

Milestone 4

Deadline: November 19

The requirements of Milestone 4 include training the models and experimenting with different hyperparameters, optimization strategies, and regularization techniques.

Training Configuration

The submission should address the following, as applicable to the project type:

  • Briefly describe the datasets used and the necessary preprocessing.

  • Provide a concise recap of the model architecture, including key components and layers.

  • Specify the complete training configuration, which may include:

    • Loss functions
    • Evaluation metrics
    • Optimizer
    • Learning rate
    • Batch size
    • Number of epochs
    • Hardware requirements
    • Other training strategies employed

Hyperparameter Experiments

  • Describe the experiments conducted to identify appropriate hyperparameter values.
  • Use tables or plots to compare performance across different settings.

Generalization & Training Stability

  • Describe the techniques used to improve:

    • Generalization
    • Training stability

  • Discuss the impact of these techniques on model performance.

Results & Observations

  • Provide quantitative and qualitative results.
  • Include other relevant observations made during the training process.
  • Include sample outputs from the trained model.

Training Artifacts

List the artifacts generated during training, such as:

  • Saved model weights
  • Checkpoints
  • Training scripts
  • Logs
  • Configuration files
  • Other relevant artifacts

Key Findings

Discuss key findings from the training process, including:

  • What worked well
  • What did not perform as expected
  • Bottlenecks encountered
  • Plans for improvement

Milestone 5

Deadline: November 26

The objective of Milestone 5 is the evaluation of model performance and analysis of results.

Evaluation Setup

The submission should address the following, as applicable to the project type:

  • Briefly restate the trained model and pipeline from the previous milestone.

  • Describe the evaluation dataset, including:

    • Size
    • Composition
    • Preprocessing steps applied during evaluation

  • Specify the evaluation environment, including:

    • Hardware
    • Software frameworks
    • Runtime setup

The evaluation environment should be documented sufficiently to ensure reproducibility.

Evaluation Metrics

  • Define the performance metrics used for evaluation.
  • Justify why the selected metrics are appropriate for the given problem.

Quantitative Results

  • Present quantitative results using appropriate tables or plots.

  • Include comparisons across:

    • Different models
    • Different configurations
    • Different hyperparameter settings

Evaluation Visualizations

Include relevant visualizations where applicable, such as:

  • Confusion matrices
  • ROC curves
  • Precision-recall curves
  • Task-specific evaluation plots

Qualitative Results

  • Show sample model outputs.

  • Include both:

    • Successful predictions
    • Failure cases

Error Analysis

  • Perform an error analysis by identifying patterns in model mistakes.
  • Discuss possible reasons for these errors.
  • Identify cases where the model performs particularly well or poorly.

Observations & Limitations

Discuss:

  • Key observations
  • Model limitations
  • Anomalies observed during evaluation
  • Gaps between expected and actual performance
  • Potential explanations for unexpected results
